# D&D Web Platform — багатокористувацький MVP

Темна fantasy-вебплатформа за презентацією: GM/гравці, кімната за кодом, персонажі й NPC, інтерактивна сітка, кубики, ініціатива, атаки, HP, журнал подій, SQLite та WebSocket.

## Вимоги
- Python 3.10 або новіший
- Браузер на комп'ютері
- Для різних комп'ютерів у межах однієї Wi-Fi/LAN-мережі — доступ до мережі й дозвіл брандмауера Windows

## Запуск у Windows / VS Code
Відкрий цю папку у VS Code: **File → Open Folder**, потім **Terminal → New Terminal**.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --host 0.0.0.0 --port 8000
```

Відкрий на комп'ютері GM: `http://127.0.0.1:8000`.

### Підключення з інших комп'ютерів
1. У терміналі Windows виконай `ipconfig`.
2. Знайди IPv4 Address активного Wi-Fi/Ethernet адаптера, наприклад `192.168.1.25`.
3. Інші гравці відкривають `http://192.168.1.25:8000` (підстав свою IP-адресу).
4. Якщо Windows Firewall запитає дозвіл, дозволь Python доступ у приватній мережі.
5. Усі мають бути в одній локальній мережі. Для гри через інтернет потрібен окремий хостинг/VPS і HTTPS/WSS.

## Як грати
1. GM створює сесію й передає код гравцям.
2. Гравці вводять код і своє ім'я.
3. Гравці створюють власних персонажів; GM може створювати NPC.
4. Перетягни токен на клітинку карти або натискай клітинки для переміщення. GM може завантажити PNG/JPG/WEBP карту.
5. Кидай кубики у форматі `1d20+5`, `2d6`, `1d100`.
6. GM запускає ініціативу, переходить до наступного ходу, виконує атаки та змінює HP.
7. Усі зміни зберігаються в `dnd.db`; після перезапуску сервера дані залишаються.

## Примітки MVP
- SQLite — локальне файлове сховище для навчального MVP; воно зберігає сесії та кампанії після перезапуску. У презентації цільова архітектура передбачає PostgreSQL, тому її варто додати перед розгортанням для реальних кампаній.
- У цій демонстраційній версії вхід здійснюється за кодом сесії та випадковим ключем доступу, а не за обліковими записами/паролями.
- WebSocket синхронізує зміни між підключеними клієнтами до одного запущеного сервера. Не запускай кілька копій сервера для однієї кампанії.
- Для відкритого доступу в інтернет потрібні HTTPS/WSS, надійна авторизація, обмеження частоти запитів, резервні копії й перевірка безпеки.
